PARTITION BY: Independent Windows Per Group

PARTITION BY divides the result into independent sub-windows and resets the window function within each one — like GROUP BY, but without losing your rows.

Run it yourself — all queries on this page use the f1db dataset, pre-loaded in the free TAOP lab. Start a session with psql taop and follow along. No setup beyond Docker.

PARTITION BY is to window functions what GROUP BY is to aggregates — but without the collapse. Instead of reducing each group to one row, it divides the result into independent partitions and applies the window function separately within each one.

Every row comes back. The window just resets at each partition boundary.

Without PARTITION BY

This query ranks every driver in race 890 by racetime, treating the whole result as one window:

  select surname, laps,
         row_number() over(order by milliseconds) as position,
         milliseconds * interval '1ms' as racetime
    from results
         join drivers using(driverid)
   where raceid = 890
order by position limit 10;

With PARTITION BY

Add PARTITION BY laps and each group of drivers who completed the same number of laps gets its own ranking, starting from 1:

  select surname, laps,
         row_number() over(
           partition by laps
           order by laps desc, milliseconds
         ) as position,
         milliseconds * interval '1ms' as racetime
    from results
         join drivers using(driverid)
   where raceid = 890
order by laps desc, position;

Drivers who completed 57 laps compete only against other 57-lap drivers. The window function restarts from 1 for each new value of laps. All rows return — including drivers who retired early with NULL raceimes, who form their own partition groups by laps completed.

The mental model

PARTITION BY col is equivalent to “run this window function as if you had filtered to WHERE col = <current value>, then put all the results back together.” Each partition is fully independent — no row in partition A affects any calculation in partition B.

You can partition by multiple columns, expressions, or the result of a CASE. Omitting PARTITION BY entirely means the whole result set is one partition — every row sees every other row, which is usually what you want for a global rank or running total.

PARTITION BY and ORDER BY inside OVER are independent of any ORDER BY at the end of the query. The inner ORDER BY defines sequence within the window; the outer one sorts the final output.
