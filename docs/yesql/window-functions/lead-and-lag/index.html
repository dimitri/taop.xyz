LEAD and LAG: Accessing Neighbouring Rows

LAG looks back one row; LEAD looks forward. Both let you compare a value to its neighbour in a sequence without a self-join.

Run it yourself — all queries on this page use the f1db dataset, pre-loaded in the free TAOP lab. Start a session with psql taop and follow along. No setup beyond Docker.

Before window functions, comparing a row to the one before it required a self-join or a correlated subquery. Both are verbose and slow. lag() and lead() replace that pattern with a single expression.

lag(expr, n) returns the value of expr from n rows back within the current window. lead(expr, n) returns the value from n rows ahead. n defaults to 1.

LAG in practice

Race 890 records each driver’s total time in milliseconds. To show the gap between each driver and the one directly ahead:

  select surname, position,
         milliseconds * interval '1ms' as racetime,
         interval '1ms' *
         (
           milliseconds - lag(milliseconds, 1) over(order by position)
         ) as diff
    from results
         join drivers using(driverid)
   where raceid = 890
order by position limit 5;

  surname  │ position │           racetime           │     diff
═══════════╪══════════╪══════════════════════════════╪═══════════════
 Hamilton  │        1 │ @ 1 hour 42 mins 29.445 secs │ ¤
 Räikkönen │        2 │ @ 1 hour 42 mins 40.383 secs │ @ 10.938 secs
 Vettel    │        3 │ @ 1 hour 42 mins 41.904 secs │ @ 1.521 secs
 Webber    │        4 │ @ 1 hour 42 mins 47.489 secs │ @ 5.585 secs
 Alonso    │        5 │ @ 1 hour 43 mins 0.856 secs  │ @ 13.367 secs
(5 rows)

lag(milliseconds, 1) over(order by position) fetches the previous row’s milliseconds value. Subtracting gives the gap to the car ahead. The race winner has no predecessor, so diff is NULL for them — the correct answer when there is nothing to compare against.

first_value() for a fixed reference point

lag() always looks back a fixed number of rows. If you want to compare every row to the same reference — the winner — use first_value() instead:

  select surname, position,
         milliseconds * interval '1ms' as racetime,
         interval '1ms' *
         (
           milliseconds - first_value(milliseconds) over(order by position)
         ) as diff_from_winner
    from results
         join drivers using(driverid)
   where raceid = 890
order by position limit 5;

  surname  │ position │           racetime           │ diff_from_winner
═══════════╪══════════╪══════════════════════════════╪══════════════════
 Hamilton  │        1 │ @ 1 hour 42 mins 29.445 secs │ @ 0
 Räikkönen │        2 │ @ 1 hour 42 mins 40.383 secs │ @ 10.938 secs
 Vettel    │        3 │ @ 1 hour 42 mins 41.904 secs │ @ 12.459 secs
 Webber    │        4 │ @ 1 hour 42 mins 47.489 secs │ @ 18.044 secs
 Alonso    │        5 │ @ 1 hour 43 mins 0.856 secs  │ @ 31.411 secs
(5 rows)

Now every driver’s gap is measured from Hamilton (position 1). The winner shows a gap of zero instead of NULL. first_value() anchors to the first row in the window and holds it constant across all rows.

LEAD for forward-looking comparisons

lead() is the mirror: it looks ahead. The classic use is detecting transitions — moments when a value changes between consecutive rows.

select tick, nb,
       case when lead(nb) over(order by tick) < nb then nb
            when lead(nb) over(order by tick) is null then nb
            else null
       end as peak
  from measures
order by tick;

Here lead(nb) returns the next row’s reading. When the next reading is smaller than the current one (the counter is about to reset), the current value is a peak. This pattern — comparing a row to its successor to detect direction changes — is one of the most common uses of lead().

Optional default value

Both functions accept a third argument: the default to return when there is no preceding or following row.

lag(milliseconds, 1, 0) over(order by position)

Returns 0 instead of NULL for the first row. Useful when NULL propagation would break downstream arithmetic.
