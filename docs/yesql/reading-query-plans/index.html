Reading Query Plans

Read EXPLAIN fluently: plan nodes, startup vs total cost, actual vs estimated rows, Buffers — so slow queries stop being a mystery.

EXPLAIN output is PostgreSQL telling you exactly what it’s doing and why. Once you can read a plan — node types, cost anatomy, row estimate mismatches, buffer usage — slow queries stop being guesswork. These lessons build that skill from the ground up.

  • EXPLAIN ANALYZE: Reading Actual vs Estimated Rows

    The most important number in EXPLAIN ANALYZE is not the timing — it is the gap between estimated rows and actual rows. A large discrepancy means the planner made its decision on wrong information.

    #EXPLAIN #EXPLAIN ANALYZE #query plans

  • Reading an EXPLAIN Plan

    EXPLAIN shows you the plan the planner chose; EXPLAIN (ANALYZE) shows what actually happened. Learn to read both, and slow queries stop being a mystery.

    #EXPLAIN #Performance #Query Plan

  • Hash Join vs Nested Loop: What the Plan Node Tells You

    Two join algorithms, two different performance profiles. The plan node tells you which one PostgreSQL chose and why — and when to question that choice.
