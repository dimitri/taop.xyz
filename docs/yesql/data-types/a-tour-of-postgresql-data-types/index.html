A Tour of PostgreSQL Data Types

PostgreSQL ships with over 70 built-in types. This tour covers the ones you will use in almost every application: booleans, numbers, text, dates, and the arrays and ranges that set PostgreSQL apart.

Run it yourself — all queries on this page use the pg_catalog dataset, pre-loaded in the free TAOP lab. Start a session with psql taop and follow along. No setup beyond Docker.

PostgreSQL comes with a long list of data types. You can see them all:

select nspname, typname
    from      pg_type t
         join pg_namespace n
           on n.oid = t.typnamespace
   where nspname = 'pg_catalog'
     and typname !~ '(^_|^pg_|^reg|_handler$)'
order by nspname, typname;

  nspname   │         typname

That returns over 70 types — just the application-developer-relevant ones. You will not need all of them, but knowing what exists is useful. Here is the tour.

Boolean

Three values: true, false, and null. The third value is where most bugs live. null = null is null, not true. Test against null with IS NULL, not = NULL. Use IS DISTINCT FROM and IS NOT DISTINCT FROM when you need comparisons that treat null as a regular value.

PostgreSQL provides boolean aggregates too: bool_and(expr) is true only when expr is true for every row in the group; bool_or(expr) is true if at least one row qualifies.

Numbers

Four families:

  • Integer: smallint (2 bytes), integer (4 bytes), bigint (8 bytes). Use integer by default; reach for bigint when you might exceed ~2 billion. serial and bigserial are shorthand for integer with a sequence.
  • Numeric/Decimal: arbitrary precision. The right choice for money and anything where you cannot tolerate floating-point rounding.
  • Floating point: real (4 bytes) and double precision (8 bytes). Fast, but imprecise. Never use for currency.
  • Special: money exists but carries locale baggage; prefer numeric.

Text

text and varchar are the same storage type; varchar(n) just adds a length check constraint. Use text for unconstrained strings, varchar(n) only when you have a real domain reason to enforce a maximum length. char(n) is padded to exactly n characters and almost never what you want.

Date and Time

  • date — calendar day, no time, no timezone
  • time — time of day, without timezone
  • timestamp — date and time, no timezone (stores exactly what you give it)
  • timestamptz — date and time with timezone awareness (stores UTC internally, displays in the session timezone)

Use timestamptz for anything that needs to be unambiguous across timezones. Use date when you only care about the calendar day.

Arrays

Any PostgreSQL type can be stored as an array: integer[], text[], timestamptz[]. Arrays support containment operators (@>, <@), overlap (&&), and unnest() to expand rows. They are useful for tags, labels, or small sets of values that belong together but do not warrant a separate table.

Ranges

PostgreSQL has native range types: int4range, daterange, tsrange, tstzrange. A range expresses a contiguous span with an inclusive or exclusive start and end. Range types support overlap, containment, and adjacency operators, and pair naturally with exclusion constraints to prevent overlapping bookings or schedules.

What makes PostgreSQL unusual

Most databases give you strings, numbers, and dates. PostgreSQL adds: geometric types, network address types (inet, cidr), full-text search types (tsvector, tsquery), JSON (json, jsonb), UUID, and extension types like PostGIS geometries. You rarely need all of them, but when you do, they are native — not strings pretending to be something else.

For JSON specifically, see JSON and Other Denormalized Types.
