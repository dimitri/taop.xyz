You already know SELECT.
This is what comes next.

Most developers avoid window functions. They look intimidating, the syntax is unfamiliar, and nobody taught them in the SQL intro course.

So instead, developers fetch data from the database and process it in Python — loops, dicts, Pandas DataFrames — code that's slow to write, slower to run, and painful to maintain.

Here's what the same problem looks like in SQL, using lag() and a window function to compute week-over-week change: 

SELECT lag(dollars, 1)
       OVER (
         PARTITION BY extract('isodow' FROM date)
         ORDER BY date
       ) AS last_week_dollars         
  FROM ...

That's it. PostgreSQL handles the calendar, the ordering, and the arithmetic — in a single query, with no application code.

This workshop is three hours of exactly that kind of revelation.

Three hours. Three skills you'll use on Monday.

Concrete outcomes, not abstract topics.

  • 01 · Time series with lag() and lead()

    Compute running totals, moving averages, and period-over-period changes directly in SQL — no Pandas, no application loop.

  • 02 · Partitioning and ranking

    Use PARTITION BY to compute top-N per group, rank results within categories, and build leaderboards in a single query.

  • 03 · Frames, aggregates, and real datasets

    Control exactly which rows participate in each window calculation. Every example runs against real-world data — NYSE trading volume, music charts, geolocation records.
