Module 01

JOIN Fundamentals

Core · 4 topics

INNER, LEFT, RIGHT, FULL OUTER, CROSS, and NATURAL joins with exact output semantics. Venn diagrams describe which rows survive — CROSS JOIN is the foundation of relational algebra, not a special case.

01
INNER JOININNER JOIN discards rows with no match on either side.
02
USING clauseUSING merges the join column once; prefer it over NATURAL JOIN.
03
LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN, CROSS JOINOuter joins preserve unmatched rows; CROSS JOIN produces the Cartesian product.
04
NULL behavior in joinsNULL comparisons yield NULL, not true, so three-valued logic governs join filtering.
Module 01 · Three-table join
select r.year,
       r.name         as race,
       d.surname      as driver,
       c.name         as constructor,
       res.positionorder as pos,
       res.points
  from f1db.results  res
  join f1db.races    r
    on r.raceid       = res.raceid
  join f1db.drivers  d
    on d.driverid     = res.driverid
  join f1db.constructors c
    on c.constructorid = res.constructorid
 where r.year = 2017
   and res.positionorder <= 3
 order by r.date, res.positionorder
 limit 12;

Top-three finishers per race in the 2017 season with driver and constructor names.

Module 02

Multi-Table JOIN Strategies

Core · 4 topics

Self-joins traverse hierarchies and compare rows within the same table. Non-equality joins match ranges. WITH RECURSIVE extends the pattern to arbitrary-depth graphs using SEARCH and CYCLE clauses.

01
Progressive enrichmentJoin from the fact table outward, adding one dimension at a time.
02
Composite FK joinsOmitting one component of a composite FK silently produces a Cartesian product.
03
Self-JOIN and the window-function alternativeSelf-JOIN aliases the same table twice to compare adjacent or related rows.
04
Recursive reach with WITH RECURSIVE, SEARCH, and CYCLE (PostgreSQL 14)WITH RECURSIVE walks a graph to any depth; CYCLE prevents infinite loops.
Module 02 · Self-JOIN consecutive races
select r.year,
       prev.round  as prev_round,
       regexp_replace(prev.name,
         ' Grand Prix$', '') as prev_gp,
       r.round     as curr_round,
       regexp_replace(r.name,
         ' Grand Prix$', '') as curr_gp,
       r.date - prev.date   as days_gap
  from f1db.races r
  join f1db.races prev
    on prev.year  = r.year
   and prev.round = r.round - 1
 where r.year = 2017
 order by r.round;

Days between consecutive race weekends in the 2017 Formula 1 calendar.

Module 03

JOIN Pitfalls

Core · 3 topics

Fan-out amplification happens silently when a join key is not unique on both sides. EXISTS and NOT EXISTS avoid double-counting; the NOT IN null trap is one of SQL's most common bugs.

01
Non-equality joinsA join condition can use any boolean expression, not only equality.
02
JOIN amplificationA one-to-many join multiplies rows, inflating every downstream aggregate.
03
The COUNT(DISTINCT) fix and the aggregate-first fixUse COUNT(DISTINCT) or aggregate before joining to collapse fan-out inflation.
Module 03 · JOIN amplification
-- Amplified (wrong): counts result rows,
-- not distinct constructors, because the
-- 1:N join multiplies each constructor
-- by all its result rows.
select c.name          as constructor,
       count(*)        as result_rows
  from f1db.constructors c
  join f1db.results res
    on res.constructorid = c.constructorid
 group by c.constructorid, c.name
 order by result_rows desc
 limit 5;

Race result rows per constructor ranked by total entries across all seasons.

Module 04

LATERAL JOINs

Core · 7 topics

LATERAL allows the right-hand subquery to reference columns from the left row. This enables top-N per group, kNN geographic search, and row-by-row correlated computation that a plain JOIN cannot express.

01
LATERAL as a manual loopLATERAL re-evaluates its subquery for each outer row with outer columns available.
02
Top-N per group with LATERALLATERAL with LIMIT fetches top-N related rows independently for each outer row.
03
Reading a LATERAL execution planEXPLAIN shows LATERAL as a Nested Loop re-run once per outer row.
04
LATERAL over geographic data: top-N cities per countryLATERAL fetches the top-N most-populous cities for each country in one pass.
05
LATERAL with distance operator: kNN geographic search (GiST <->)LATERAL passes the outer row's location to a GiST nearest-neighbor lookup.
06
LATERAL for social graphLATERAL stops scanning each user's messages after finding the most-retweeted one.
07
Hashtag co-occurrence via array unnesting and self-joinSelf-joining the unnested hashtag array produces all co-occurring pairs per tweet.
Module 04 · LATERAL Top-N per driver
select d.surname       as driver,
       top3.race,
       top3.pos,
       top3.points
  from f1db.drivers d
  join lateral (
    select r.name  as race,
           res.positionorder as pos,
           res.points
      from f1db.results res
      join f1db.races   r
        on r.raceid = res.raceid
     where res.driverid = d.driverid
       and r.year       = 2017
       and res.points   > 0
     order by res.points desc
     limit 3
  ) top3 on true
 where d.surname in (
   'Hamilton','Vettel','Bottas'
 )
 order by d.surname, top3.points desc;

Top three highest-scoring race results in 2017 for Hamilton, Vettel, and Bottas.

Module 05

Aggregation and Window Functions with JOINs

Core · 3 topics

Combining GROUP BY and window functions with JOINs requires careful ordering. FILTER and CASE inside aggregates often eliminate the need for a second join pass.

01
GROUP BY after JOINAggregate after joining only when each joined row represents exactly one event.
02
Filtered aggregates with FILTER clauseFILTER clause applies a per-aggregate condition in a single table scan.
03
Window functions over joined dataWindow functions run after joins, operating over the fully enriched joined relation.
Module 05 · Cumulative championship points
select d.surname              as driver,
       r.round,
       left(r.name, 14)       as race,
       res.points,
       sum(res.points) over (
         partition by d.driverid
         order by r.date
         rows between unbounded preceding
                  and current row
       )                      as cum_pts
  from f1db.results res
  join f1db.drivers d
    on d.driverid = res.driverid
  join f1db.races   r
    on r.raceid   = res.raceid
 where r.year = 2017
   and d.surname in ('Hamilton', 'Vettel')
 order by d.surname, r.date;

Cumulative championship points per race for Hamilton and Vettel across the 2017 season.

Module 06

Complex Query Composition

Core · 7 topics

WITH (CTEs), nested subqueries, and LATERAL chain together into readable multi-step computations. The MATERIALIZED option controls whether PostgreSQL treats a CTE as a fence or inlines it as a subquery.

01
CTEs for readability and multi-step logicWITH clauses name intermediate relations, turning complex queries into sequential readable steps.
02
Subqueries in join positionA subquery in FROM pre-aggregates before joining, preventing fan-out amplification.
03
Semi-JOIN: EXISTSEXISTS stops at the first match, preventing fan-out duplication of outer rows.
04
Anti-JOIN: NOT EXISTSNOT EXISTS keeps rows that have no match on the inner side.
05
The NOT IN null trapNOT IN silently returns zero rows when the subquery contains any NULL.
06
Set operators: UNION, INTERSECT, EXCEPTUNION, INTERSECT, and EXCEPT combine same-schema relations vertically, deduplicating by default.
07
DISTINCT ONDISTINCT ON picks one row per group; ORDER BY selects which row.
Module 06 · Anti-JOIN NOT EXISTS
select forename, surname,
       constructors.name    as constructor,
       count(*)             as races,
       count(distinct status) as reasons
  from f1db.drivers
       join f1db.results      using(driverid)
       join f1db.races        using(raceid)
       join f1db.status       using(statusid)
       join f1db.constructors using(constructorid)
 where date >= date '1978-01-01'
   and date <  date '1978-01-01'
                + interval '1 year'
   and not exists (
     select 1
       from f1db.results r
      where position is not null
        and r.driverid = drivers.driverid
   )
 group by constructors.name, driverid
 order by count(*) desc limit 10;

Drivers who entered at least one 1978 race without ever finishing.

Module 08 · Normalized vs pre-aggregated
-- Normalized: re-computed on every request
select c.name                           as constructor,
       count(distinct res.driverid)     as drivers,
       count(distinct res.raceid)       as races,
       count(*) filter(
         where res.positionorder = 1)   as wins,
       sum(res.points)                  as total_points
  from f1db.constructors c
  join f1db.results res
    on res.constructorid = c.constructorid
 group by c.constructorid, c.name
 order by total_points desc
 limit 10;

Constructor career totals: distinct drivers, races entered, wins, and cumulative points.
